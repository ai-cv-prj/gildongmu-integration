3. 쉽게 고르는 순서

1기준부터 측정먼저 YOLO26n + Mask2Former만 실행해서 실제 스마트폰의 FPS, 지연시간, 발열을 기록한다.
2거리 정보가 꼭 필요한지 확인정확한 거리값이 필요하면 ARCore Depth를 먼저 붙인다. “곧 충돌하는가”만 중요하면 TTC형을 먼저 시험한다.
3ARCore 대안이 필요하면Lite-Mono-Tiny를 비교한다. 깊이 품질을 더 보고 싶으면 Depth Anything V2는 저주기 비교용으로만 사용한다.

추천 실험은 처음부터 많게 잡지 않는다

기준안 YOLO26n + Mask2Former ① 거리 필요 → + ARCore Depth ② 거리 숫자 불필요 → + TTC ③ ARCore 대안 필요 → + Lite-Mono-Tiny 그 뒤 실제 오류가 있을 때만 → EfficientSAM-Ti 추가

EfficientSAM-Ti는 “필수 모델”이 아니다. YOLO bbox 안에 배경 픽셀이 섞여 거리값이 자주 틀어지는 문제가 확인될 때만 장애물 마스크 정밀화 용도로 추가한다.

4. 실시간 구현에서 꼭 지킬 것

  • 모든 모델을 카메라 FPS와 1:1로 돌리지 않는다. YOLO, Mask2Former, Depth는 서로 다른 주기로 실행 가능하다.
  • 프레임 큐를 길게 쌓지 않는다. 추론 중 새 프레임이 들어오면 오래된 프레임은 버리고 최신 프레임을 사용한다.
  • ROI를 유지한다. 이미 효과가 확인된 진행방향 ROI를 위험 판단과 후속 모듈 실행 조건으로 활용한다.
  • 평균 FPS만 보지 않는다. end-to-end latency, 발열, 배터리, 장애물 miss rate, 거리오차를 같이 측정한다.
  • 조건부 실행을 사용한다. EfficientSAM 같은 추가 모듈은 “보도 위 + ROI 안 + 위험 후보”일 때만 실행한다.
