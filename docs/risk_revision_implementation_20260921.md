# 위험 판단 수정 구현 및 8개 영상 비교

2026-09-21. 사용자 피드백에 따른 코드 수정은 반영됐으며, 결과 위치는
outputs/experiments/2026-09-21_risk-detection-evaluation/06_attempt-2_sidewalk-guided-roi이다. 기준 영상은 같은 실험 폴더의 04_attempt-1_fixed-roi에 있는 기존 8개 결과다.
실행 상태 및 검증 수치는 결과 폴더 manifest.json에서 확인한다.

## 구현 내용

### 넓어진 고정 하단

- 진행 ROI: (0.42,0.45), (0.58,0.45), (0.98,1), (0.02,1).
- 근접 관찰 ROI: (0.205,0.75), (0.795,0.75), (0.98,1), (0.02,1).
- 최하단 폭은 80%에서 96%로 늘었다.
- 근접 관찰 ROI의 윗변 폭은 40%에서 59%로 늘었다.
  계획의 약 60%에서 기본 진행 사다리꼴 내부 조건을 만족하도록 좌우 0.005씩 조정했다.
- 전체 화면의 YOLO 탐지와 원본 박스·신뢰도·클래스는 유지한다.

### 보도 방향 보조

src/path_roi.py의 SidewalkGuidedROI를 추가했다.
Mask2Former 결과를 동일 프레임의 ROI 계산에 사용하도록 src/pipeline.py 순서를 조정했다.
모델 추론 횟수는 이전과 같다.

- walkable만 사용하며 하단 y=0.83~0.98, x=0.20~0.80과 연결된 보도 성분을 고른다.
- 계산용 마스크 너비는 270픽셀이며 종횡비를 유지한다. 작은 끊김에 3×3 closing을 적용한다.
- y=0.55~0.90의 8개 가로 띠를 관찰한다.
- 유효한 띠 5개 이상, 좌우 경계가 보이는 띠 3개 이상, 높이 범위 0.12 이상을 요구한다.
- 화면 양쪽으로 마스크가 잘린 띠와 큰 분기/공백은 방향 근거에서 제외한다.
- 직선 회귀 잔차 0.04 이하일 때만 방향 후보로 사용한다.
- 0.2초 연속 후보 확인 후, 0.3초 시간 상수로 완화한다.
- 상단 중심 이동 범위는 기본 중심 ±0.15W, 이동 속도 상한은 0.12W/초이다.
- 하단과 근접 관찰 ROI는 움직이지 않는다.
- 마스크가 나빠지면 0.5초 유지 후 0.5초에 걸쳐 고정 ROI로 복귀한다.
- 전체 화면이 walkable이면 신뢰할 경계가 없으므로 고정 ROI를 사용한다.
- ROI는 convex 여부와 화면 경계를 검사한다. 보도 마스크의 장애물 구멍을 ROI에서 제거하지 않는다.

프레임별 roi 필드에 fixed / sidewalk / held / returning, 중심, 회귀 잔차,
방향 신뢰도, 실패 사유를 기록한다.
보도 방향은 보이는 지면 모양에 대한 보조이며 실제 3D 진행 방향·이동 의도 추정이 아니다.
방향이 적용된 진행 ROI와 넓은 고정 근접 관찰 ROI는 별도로 평가한다.

### 기둥 등 지면 고정 물체

src/risk_proximity.py와 클래스별 접점 처리를 추가했다.
기본 정적 지면 정책 클래스는 pole, bollard, tree_trunk, potted_plant, fire_hydrant,
utility_box, parking_meter, kiosk, bench, barricade, trash_bin이다.
이는 클래스 기반 정책이며 물체의 실제 정지 여부를 측정한 결과는 아니다.

- 하단 띠 높이: min(bbox 높이×0.15, 화면 높이×0.02).
- 정적 지면 클래스의 접점 폭은 bbox 중앙 부분을 사용한다.
- 접점 y/H<0.65: far, 0.65~0.88: middle, 0.88 이상: near.
- 하단이 화면 경계에서 잘리면 접점 구간은 unknown.
- 경로 관련성이 있는 정적 물체는 far→기본 monitor, middle/unknown→caution, 신뢰 가능한 near→danger.
- 짧고 유효한 TTC는 앞 단계에서도 등급을 올릴 수 있다.
- 실제 가까운 정적 물체에는 TTC가 없어도 danger를 줄 수 있다.
- 정적 지면 클래스의 화면상 수평 이동으로 lateral_entry 경고를 만들지 않는다.

NEAR/MIDDLE/FAR는 화면상 지면 접점 구간이며 미터 거리 표시가 아니다.
사람 등 이동 가능 클래스는 넓은 근접 관찰 ROI와 측방 진입 규칙을 사용하므로,
화면 접점 구간 MIDDLE에서도 danger가 될 수 있다.
카메라 장착 방향·높이·화각은 영상 내 고정, 위치는 이동한다고 가정한다.

### 경고 해제와 관측 소실

src/alert_policy.py에서 경고 해제 조건과 이벤트 연결을 변경했다.

- 새 위험은 현재 탐지만으로 즉시 상향하며 ID 확정을 기다리지 않는다.
- 진입 겹침 기준 20%, 경로 이탈 후보 기준 10%와 수평 여유 0.02W를 사용한다.
- 안정된 관측·운동 이력·현재 ROI 조건에서 이탈 근거가 0.5초 지속돼야 해제한다.
- ROI가 이동하거나, 박스가 잘리거나, 시각/카메라 품질이 불안정하면 이탈 확인에 사용하지 않는다.
- 낮아진 근접/긴급성이 충분히 관측되면 danger→caution으로 낮춘다.
- 불확실한 하향은 최대 0.8초 유지한 뒤 uncertainty_timeout으로 기록한다.
  이때 경고를 영구 고정하지 않으며 안전 확인을 의미하지 않는다.
- 관측이 0.5초 이상 사라지면 cleared 대신 lost / visibility_lost 이벤트를 남긴다.
- 프레임에 없는 추적 예측 박스는 표시하지 않는다.
- ID 변경 후에도 0.3초 안의 같은 클래스, IoU≥0.5, 면적비 0.5~2.0,
  양방향으로 유일한 대응인 경우에만 경고 이벤트를 승계한다.
- 군중에서 대응이 모호하거나 이전 ID가 여전히 관측되면 상태를 다른 사람에게 넘기지 않는다.

로그의 hold_reason / release_reason / alert_status / event_identity_bridged로 상태 이유를 확인할 수 있다.
image_path_exit_confirmed는 화면 경로 이탈 확인일 뿐이며, safety_confirmed는 항상 false로 기록한다.

## 사용자 추가 지적: 후속 검증 필요

**카메라 화면에서 벗어났더라도 실제 카메라를 든 주행자 가까이에 있을 수 있다.**
사용자는 이번에는 제안한 해제 방식을 유지하고, 이 부분을 나중에 다시 확인하도록 요청했다.

따라서 이번 구현은 시야 밖 충돌 위험 문제를 해결한 것으로 간주하지 않는다.
관측 소실·화면상 경로 이탈을 실제 거리 증가나 물리적 안전 확인으로 해석하면 안 된다.
후속 검증에는 옆으로 스쳐 지나감, 옆에 계속 붙어 있음, 카메라 사각으로 진입함을 구분하는 장면이 필요하다.
센서 범위·신체 기준 충돌 영역·가려짐 이후 상태 유지 정책은 별도 과제다.

## 검증

- 기존 72개 테스트와 신규 15개 회귀 테스트, 총 87개 통과.
- 기존 테스트의 관측 소실 기대값은 새로운 lost 의미에 맞게 갱신했다.
- 신규 테스트: 보고된 기둥/사람 좌표, 가까운 무ID 정적 장애물, 정지 기둥의 수평 이동,
  접점 띠 상한, 잘못된 설정, 전체 보도/빈 마스크, 방향 변화 제한·복귀,
  시간 오류, 지속적 이탈, 불확실성 만료, 소실, 확정 ID 교체, 군중의 모호한 연결.
- 같은 YOLO 탐지·ID와 새 Mask2Former 추론으로 지정 구간 202프레임을 사전 재생했다.
- G24P_004 frame 271: 기둥 raw danger→caution.
- G24P_003 frame 271: 사람 raw monitor→danger.
- 사전 검증은 전체 재추론 결과를 대신하지 않으며, 전체 실행에서도 같은 장면을 검증한다.
- src/traffic.py, src/traffic_association.py, src/visualization.py, src/obstacle.py가 HEAD와 동일함을 확인했다.
- traffic 설정도 HEAD와 동일하다. 위험 기능을 켠 신호등 호출/필터/표시 테스트가 통과했다.

## 전체 비교 실행

- 입력 8개, 총 5,591프레임.
- 새 결과: 원본 1080×1920 및 명목 FPS 유지. YOLO + Mask2Former + BoT-SORT + 수정 위험 판단.
- 비교 결과: 왼쪽 BEFORE, 오른쪽 AFTER. 각 화면을 540×960으로 줄여 제목과 함께 1080×1008로 저장.
- 새 결과와 비교 결과 모두 모든 프레임을 저장하고 다시 디코딩해 수를 확인한다.
- 기존/새 JSONL을 같은 프레임끼리 비교해 탐지 목록의 변경 여부를 별도로 기록한다.

- 음성은 포함하지 않는다.
- 모델별 한 번만 로딩하며 영상마다 위험·추적·ROI 상태는 초기화한다.
