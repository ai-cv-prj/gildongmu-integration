# ROI 방식 비교와 8개 영상 위험 표시 검토

2026-09-21. 대상은 data/samples/sample1의 MP4 8개, 총 5,591프레임이다.
결과 위치: outputs/experiments/2026-09-21_risk-detection-evaluation/04_attempt-1_fixed-roi.
전체 프레임 YOLO + Mask2Former + BoT-SORT를 실행하며, 이번 검토 설정에서 확대 TTC 위험 반영을 켰다.
신호등 코드는 수정하지 않았다. 이번 실행 모드는 기존 기본값인 both(장애물+보도)이다.

## 1. ROI를 먼저 잘라도 되는가

가능하다. 판단하려는 대상이 ROI 내부 객체뿐이라면, 먼저 자른 영상에서 탐지하고 원본 좌표로 복원하여 위험을 판단할 수 있다.
다만 고정 ROI는 물리적 거리 측정값이 아니다. ROI에 들어왔다는 사실만으로 실제 가까운 거리나 충돌을 확정할 수 없다.

이번 코드가 전체 화면을 먼저 탐지하는 이유는 ROI 밖 객체의 진입 전 이력을 확보하기 위해서다.
이는 실제 위험 재현율이 검증됐다는 뜻은 아니다. 같은 입력 크기에서는 ROI 확대가 작은 객체 탐지에 유리할 수도 있다.

### 실제 비교 조건

- 영상별 균등한 32프레임, 총 256프레임. 연속 추적/조기 경고 평가는 아니다.
- 같은 YOLO 가중치, CUDA, conf=0.25, imgsz=640, NMS 설정 유지.
- 전체 화면 / 진행 ROI의 외접 사각형 / 외접 사각형에서 진행 ROI 밖을 검게 처리하는 세 방법.
- 사각형 범위: 원본의 x=10~90%, y=45~100%.
- 각 방식 워밍업 3회 후 실행 순서를 번갈아 측정했다.
- 시간은 준비·YOLO 호출·CPU 결과 변환을 포함한다. 영상 디코딩·Mask2Former·추적·표시·인코딩은 제외했다.
- ROI 내 탐지: 원본 좌표로 복원한 박스 하단 15% 띠가 진행 ROI와 20% 이상 겹치는 경우.
- 아래 탐지 건수는 프레임별 관측의 합이다. 고유 물체 수나 정답 탐지 수가 아니다.

| 방식 | 실제 YOLO 입력 H×W | 중앙값 | 평균 | P95 | ROI 내 탐지 관측 |
| --- | --- | ---: | ---: | ---: | ---: |
| 전체 화면 | 640×384 | 8.84 ms | 9.76 ms | 13.57 ms | 387 |
| 외접 사각형 자르기 | 640×544 | 9.42 ms | 10.69 ms | 14.89 ms | 538 |
| 사다리꼴 밖 마스킹 후 자르기 | 640×544 | 10.16 ms | 11.22 ms | 15.75 ms | 407 |

이번 조건에서는 전체 화면 추론이 더 빨랐다.
Ultralytics의 rect 최소 패딩 때문에 같은 imgsz라도 실제 텐서 크기가 달라진다.
잘린 영상의 종횡비가 바뀌면서 입력 픽셀 수는 오히려 약 42% 증가했다.
ROI 확대에 따라 객체가 더 크게 보인다는 효과도 동시에 발생한다.
공식 동작 설명: https://docs.ultralytics.com/modes/predict/#inference-arguments

같은 클래스·IoU≥0.5로 대응시킨 관측은 아래와 같다. 잘림 영향을 줄이기 위해 양쪽 박스를 공통 외접 사각형으로 자른 뒤 비교했다.

| 비교 | 대응됨 | 전체 화면 쪽에만 대응 없는 관측 | ROI 쪽에만 대응 없는 관측 |
| --- | ---: | ---: | ---: |
| 전체 vs 사각 ROI | 326 | 61 | 212 |
| 전체 vs 사다리꼴 ROI | 220 | 167 | 187 |

정답 라벨이 없으므로 '추가 관측=성공', '대응 없음=미탐'으로 해석하면 안 된다.
박스 위치 변화, 클래스 오류, 오탐도 차이에 포함된다.
사각 ROI의 탐지 관측이 늘었다는 사실만으로 정확도가 높다고 결론 낼 수 없다.

현재 결론은 **전체 화면 탐지를 유지하고, ROI는 위험 점유·진입 판단에 사용**하는 것이다.
측방 객체의 사전 관측을 보존하면서 이번 입력 조건에서 YOLO 처리 시간도 유리했다.
ROI 확대 탐지를 추가로 사용할지는 실제 정답 박스·위험 구간을 붙여 확인해야 한다.
비교할 지표는 탐지 precision/recall, 위험 구간 recall, 최초 경고 선행 시간, 분당 오경고, 전체 파이프라인 지연이다.

원본 측정: outputs/experiments/2026-09-21_risk-detection-evaluation/03_roi-crop-speed-check/summary.json 및 frames.jsonl.
영상별 비교 이미지 8장도 같은 폴더에 있다.

## 2. TTC·접근 속도·거리의 구현 범위

이전 기본 구현도 TTC 값을 계산했지만 등급에는 반영하지 않았다.
기존 기본 등급은 근접 ROI 점유→danger, 진행 ROI 점유→caution, 경로 밖 측방 진입 예측→caution이었다.
이번 8개 검토 영상은 별도 review_config.yaml에서 ttc_alerts=true를 켰다.
기본 configs/inference.yaml의 ttc_alerts=false는 유지한다.

추가 로그/표시 항목:
- relative_expansion_per_s: 정규화 bbox 높이의 상대 변화율 q=(dh/dt)/h.
- approach_state: approaching / receding / steady / unknown.
- ttc_scale_s: 양의 유효한 확대율에 대한 TTC≈1/q=h/(dh/dt).
- ttc_invalid_reason: 이력 부족, 불안정한 운동, 경계 잘림 등으로 TTC를 사용할 수 없는 이유.
- 화면의 size +30%/s는 '현재 높이 대비 초당 30% 확대'를 의미하며 m/s가 아니다.

실험용 등급 규칙:
1. 근접 ROI 점유는 운동 이력을 기다리지 않고 danger.
2. 진행 ROI 점유는 caution.
3. 유효한 TTC≤1.5초이면서 진행 ROI를 점유하면 danger로 올린다.
4. TTC≤3초인 진행 ROI 객체에는 approaching 사유를 기록한다. 이 객체는 이미 경로 점유 caution이다.
5. 바깥 객체가 0.8초 이내 진행 ROI에 진입할 것으로 예측되면 조건에 따라 caution.
6. 이력·ID가 없는 신규 객체도 1~2번 점유 규칙으로 즉시 판단한다.

최소 0.2초·3개 관측, 최근 0.6초 이력, 원본 시각, 카메라 움직임 검사, 회귀 오차, 경계 잘림 조건이 적용된다.
카메라 검사는 급격한 변화를 제한하는 장치이며 실제 자세 보정이나 정밀 ego-motion 분리는 아니다.
박스 자세·가림·크기 변동이나 완만한 카메라 회전 때문에 유효 조건을 통과한 TTC도 틀릴 수 있다.
근접 ROI는 화면 위치를 통한 근사이고, 이 값만으로 미터 거리를 알 수 없다.

핀홀 가정에서 h=fH/Z이면 q≈(-dZ/dt)/Z이다.
따라서 화면 확대만으로는 접근속도/거리의 비율을 추정할 뿐, 거리 Z와 접근속도를 각각 미터 단위로 분리할 수 없다.
정지한 물체에도 보행자가 접근하면 확대가 발생하며, 이는 상대 충돌 판단에는 필요한 신호다.
반면 측방 횡단은 확대가 거의 없을 수 있어 TTC를 모든 위험의 필수 조건으로 삼지 않았다.

실제 거리(m)·접근속도(m/s)는 아직 미구현이다.
현재 MP4에는 캘리브레이션·깊이·동기화된 센서 정보가 없으므로 값을 만들어 표시하지 않았다.
추가 단계는 모바일에서 깊이와 카메라 자세를 함께 수집하거나, 고정 장착 높이·내부 파라미터·지면 가정을 보정하여 거리 추정을 검증하는 것이다.
ARCore는 이 모바일 수집 단계의 선택지이며, 기존 RGB MP4를 처리하는 현 파이프라인에 바로 끼우는 대안은 아니다.

ROI 좌표·임계값·수식 전체는 risk_mvp.md에 기록했다. 모두 초기 실험값이며 데이터로 최적화된 값이 아니다.

## 3. tracking_comparison 영상의 의미

outputs/experiments/2026-09-21_risk-detection-evaluation/02_tracking-backend-check의 비교 영상은 원본 첫 120프레임의 동일한 YOLO 탐지에
ByteTrack과 BoT-SORT가 각각 어떤 ID를 붙이는지 비교한 것이다.
ROI 자르기, 위험 등급 정확도, 거리/TTC 성능을 비교한 영상이 아니다.

| 항목 | ByteTrack | BoT-SORT |
| --- | ---: | ---: |
| 동일 YOLO 관측 | 1,392 | 1,392 |
| ID가 부여된 관측 | 998 | 1,183 |
| ID 없는 관측도 유지 | 394 | 209 |
| 추적 평균 처리 시간 | 0.944 ms | 8.392 ms |
| 추적 P95 | 1.260 ms | 9.569 ms |

추적 시간은 해당 샘플의 CPU 후처리 측정이다. GPU YOLO 시간과 직접 합쳐 일반 성능값으로 쓰지 않는다.
ID가 많이 붙었다고 실제 ID 정답률이나 ID switch가 좋다고 확정할 수 없다.
이전 결과는 탐지 박스를 버리지 않는 연결 방식과 실행 가능성을 확인한 것이다.

## 4. 결과 영상 읽는 법

- 청록 실선/옅은 채움: PATH ROI, 진행 경로 가정.
- 자홍 실선/옅은 채움: NEAR ROI, 근접 영역 가정.
- 빨강 DANGER / 노랑 CAUTION / 회색 MONITOR: 표시용 위험 등급.
- #번호: 선택적 추적 ID, NEW: 아직 ID가 없는 현재 탐지.
- TTC~숫자: bbox 확대 기반 실험값. TTC --: 사용 가능한 값이 없음.
- size ±숫자%/s: 박스 높이 상대 변화율.
- entry~숫자: 화면상 ROI 진입 예상 시간.
- 초록/핑크 배경: 기존 Mask2Former 보도/횡단보도 결과. 이번 마스크 투명도는 0.30.
- 등급 표시에는 0.3초 하향 유지 시간이 포함될 수 있다. JSONL의 risk_level은 현재값, alert_level은 표시값이다.
- 카메라 시야 밖 객체를 감지하는 기능은 없으며, 객체가 화면에 검출된 이후부터 평가한다.

원본 1080×1920 크기와 명목 FPS를 유지하고 모든 프레임을 순서대로 처리한다. 원본 오디오는 출력하지 않는다.
실험 설정·각 영상 프레임 수·디코딩 검증·관측 통계는 결과 폴더의 manifest.json에 저장한다.
프레임별 세부 판단은 각 MP4와 같은 이름의 .risk.jsonl에 저장한다.
이 산출물은 위험 규칙을 육안 검토하기 위한 것으로, 위험 정답률을 검증한 성능 보고서가 아니다.

자동 테스트: 72개 통과. 기존 신호등 로직·표시 및 traffic 설정은 보존했다.
