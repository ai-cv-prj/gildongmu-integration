## 기준과 반환 형식

- 신호등 기본 검출 신뢰도 0.25, YOLO 입력 크기 960, 색상 분류 기준 0.60.
- 횡단보도 연결 기준은 기존 YAML의 `crosswalk_min_confidence`(기본 0.50)를 사용합니다.
  기존처럼 신호등과 횡단보도의 검출 기준을 독립적으로 유지하기 위해 YOLO 호출에는
  두 기준 중 작은 값을 적용합니다. 그 반환 범위의 횡단보도 후보를 모두 표시합니다.
- 횡단보도 위치 조건: 아래쪽 ≥ 높이 55%, 중심의 가로 편차 ≤ 너비 30%.
- 기존 대상 매칭: IoU ≥ 0.20, 중심 이동 ≤ 이전 박스 대각선 0.50,
  가로·세로·면적 각각 2배 이내, 상위 점수 차이 ≥ 0.15.
- 연속 연결 확인은 신호등·횡단보도 각각 IoU ≥ 0.30이며 기본 3프레임입니다.

`TrafficSignalPipeline.predict(frame, frame_id=..., captured_at_ms=...)`는 다음을 반환합니다.

| 필드 | 의미 |
| --- | --- |
| `detections` | 신호등 전체. 픽셀 `xyxy`, 검출 `confidence`, `selection_status`, `signal_state`, `color_confidence`, `track_id` |
| `crosswalks` | 표시 가능한 횡단보도 전체. 픽셀 `xyxy`, 신뢰도, `crosswalk_status`, `exclusion_reasons` |
| `selected_detection_index` / `candidate_detection_index` | 현재 `detections`의 선택/확인 중 인덱스. 대상 번호와는 다름 |
| `detected_signal_count` | 신호등 개수 |
| `detected_crosswalk_count` | 연결 신뢰도를 통과한 횡단보도 수 |
| `crosswalk_candidate_count` | 표시 횡단보도 후보 수 |
| `crosswalk_diagnostics` | 검출·연결 상태, 기준 통과 수, 표시 목록의 `selected_crosswalk_index` |
| `association` | 선택 사유·근거, 추적 번호, `tracking.camera_motion`, `tracking.target_change` |

`association.crosswalk_index`는 연결 기준 통과 목록의 인덱스입니다. 표시용 `crosswalks`에는
기준 미달 후보도 포함되므로 이 인덱스로 표시 박스를 선택하지 않습니다.
`crosswalk_diagnostics.selected_crosswalk_index`나 각 박스의 `crosswalk_status=used`를 사용합니다.
확인 중·차단 중에는 최종 선택 인덱스와 색상 신뢰도가 null이고 최종 색상은 unknown입니다.

영상 처리기는 `(frame_id - 1) * 1000 / 원본 FPS`를 시각으로 전달합니다. 영상마다 reset하고
모델은 재사용합니다. 직접 `predict(frame)`만 호출하는 경우에는 이전 API 호환을 위해
자동 연속 번호와 200ms 간격을 사용합니다. 실제 시각이 있으면 명시적으로 전달하세요.

OpenCV 영상 표시는 기존 환경처럼 영문입니다. TARGET은 최종 안내 대상,
CANDIDATE는 확인 중, UNSELECTED는 미선택입니다. 검출 신뢰도(det)와 색상 분류
신뢰도(color)를 구분합니다. 청록 횡단보도는 연결 판단에 사용됐다는 뜻이며 연결 성공을
뜻하지 않습니다. 도보 마스크와 장애물 표시 방식은 유지합니다.

## 실시간 전환 시 확인 시간 검토 (2026-09-22, 미구현)

실시간 입력으로 바꾸는 것만으로 3프레임 확인 시간이 같아지지는 않습니다.
카메라 촬영 속도보다 **선택 로직이 실제로 처리하는 프레임의 시각 간격**이 중요합니다.

**기존 `gildongmu-test-app`의 신호등 모드는 초당 최대 5회로 설정되어 있습니다.**
설정 위치는 `backend/static/js/app.js`의 `TRAFFIC_SETTINGS.target_fps = 5`이며,
대상 연결 확인은 기본 3프레임 연속입니다. 초당 5회가 유지되면 첫 확인부터
세 번째 확인까지 약 **0.4초**입니다. 최소 0.4초를 별도로 검사하는 로직은 아닙니다.

| 적용 대상 | 판단 주기 | 한 프레임 간격 | 첫 번째 확인부터 세 번째 확인까지 |
| --- | --- | --- | --- |
| 기존 테스트 앱의 신호등 모드 | 초당 최대 5회 | 5회 유지 시 0.2초 | 약 0.4초 |
| 통합 프로젝트의 초당 30장 영상 예시 | 초당 30프레임 기준 | 약 0.033초 | 약 0.067초 |

위 시간은 일정한 간격으로 처리할 때의 예시입니다. 첫 확인부터 세 번째 확인까지는
두 간격이므로 `2 / 초당 판단 횟수`로 계산합니다. 통합 프로젝트는 현재 입력 영상의
원본 프레임 속도를 따르며 모든 영상이 초당 30장은 아닙니다. 실시간 처리 지연이나
프레임 누락이 있으면 실제 확인 간격도 달라집니다.

후속 작업에서는 **연속 프레임 수와 최소 확인 시간을 함께 적용하는 방식**을 검토합니다.
같은 신호등·횡단보도 연결이 연속 확인되고, 첫 후보의 촬영 시각부터 최소 시간이
지났을 때 선택·변경·재확인을 확정하는 방식입니다. 최소 시간 값은 아직 정하지
않았으며 실제 지연과 오인식 결과를 보고 결정합니다. 초당 5회 기준의 약 0.4초는
비교 기준이지 확정한 설정값이 아닙니다.

실시간 연결 시 실제 촬영 시각을 전달하고, 현재 직접 호출용 200밀리초 가정에
의존하지 않도록 확인해야 합니다. 음성 안내에 계획한 같은 대상·같은 색의
2프레임 연속 확인 조건은 대상 선택의 3프레임 조건과 별도로 검토합니다.
이번에는 후속 검토 사항만 기록했으며 실행 로직과 설정값은 변경하지 않았습니다.
