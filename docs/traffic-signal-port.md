사용자 요청에 따라 **음성 안내는 실시간 입력 전환 때 추가**합니다.

검출 자체가 없는 프레임을 복원하거나 점멸 상태를 인식·저장하지 않습니다.

## 대상 선택 정책

1. 신호등 하나만 보이면 즉시 임시 선택하고 색상을 분류합니다 (`single_signal`).
2. 임시 대상을 추적하는 중 여러 신호등이 보이면 색상 출력을 보류하고 횡단보도 기준으로
   후보를 다시 찾습니다. 기본 3프레임 연속 확인하면 `crosswalk_matched`로 확정합니다.
3. 같은 신호등으로 확정되면 기존 BoT-SORT ID를 유지하고, 다른 신호등이면 그 객체의 ID를
   사용합니다. 확인 중에는 `waiting_for_temporal_consistency`, 확정 시에는 `matched`입니다.
4. 횡단보도 연결을 확정한 대상은 정상 추적 중 다른 후보로 교체하지 않습니다.
   횡단보도 방향 변화나 다른 신호등의 높은 검출 신뢰도로 재선택하지 않습니다.
5. 추적이 끊기거나 매칭이 모호하면 즉시 해제하고 현재 프레임부터 새 선택을 시작합니다.
   최소 유지 시간과 미검출 보관 시간 등 2.5초 조건은 없습니다.

임시 대상의 연결 확인을 시작한 뒤에는 횡단보도·방향이 사라지거나 하나만 검출되어도,
현재 대상의 추적이 유지되는 동안 확인 완료 전까지 색상을 보류합니다. 후보 ID가 바뀌거나
연결 근거가 끊기면 연속 확인 횟수를 초기화합니다. `association_stable_frames`는 설정 가능합니다.
트래커는 `track_buffer=0`이며 업데이트 뒤 미검출 목록을 비워 다음 프레임에 과거 ID를 복원하지 않습니다.
영상마다 `reset()`으로 선택기와 추적기를 함께 초기화합니다. 서로 다른 영상 파이프라인의 ID는 독립적입니다.

## 기준과 반환 형식

- 신규 신호등 기본 검출 신뢰도 0.25, YOLO 입력 크기 960, 색상 분류 기준 0.60.
- 저신뢰 연결 하한은 `min(0.1, traffic.conf)`이며, 신호등 신규·고신뢰 기준은 `traffic.conf`입니다.
- 횡단보도의 독립 설정은 유지합니다. 표시 하한은 `min(traffic.conf, crosswalk_min_confidence)`,
  연결 하한은 `crosswalk_min_confidence`(기본 0.50)입니다.
  YOLO 호출은 복구용 하한까지 낮추되 횡단보도는 원래 표시·연결 기준으로 다시 걸러냅니다.
- 횡단보도 위치: 아래쪽 ≥ 높이 55%, 중심의 가로 편차 ≤ 너비 30%.
- 연속 연결 확인: 신호등 ID 동일 + 이동 보정한 횡단보도 IoU ≥ 0.30, 기본 3프레임.
- 프레임 번호 불연속·시각 역순·1초 초과 간격·해상도 변경이면 선택·추적 이력을 초기화합니다.
- BoT-SORT: match_thresh 0.8, fuse_score 미사용, ReID 비활성.

`TrafficSignalPipeline.predict(frame, frame_id=..., captured_at_ms=...)` 반환 형식:

| 필드 | 의미 |
| --- | --- |
| `detections` | 중복·미연결 저신뢰 검출 제거 후 신호등. 픽셀 `xyxy`, `confidence`, `selection_status`, `signal_state`, `color_confidence`, `track_id` |
| `crosswalks` | 내부 판단·진단용 횡단보도. 픽셀 `xyxy`, 신뢰도, `crosswalk_status`, `exclusion_reasons` |
| `selected_detection_index` / `candidate_detection_index` | 현재 `detections`의 선택/확인 중 인덱스. 객체 ID와 다름 |
| `detected_signal_count` | 필터 적용 후 표시·선택에 사용하는 신호등 수 |
| `raw_detected_signal_count` | 중복 제거·추적 연결 필터 적용 전 신호등 검출 수 |
| `suppressed_signal_count` | 중복으로 제거한 신호등 수 |
| `unmatched_low_confidence_count` | 중복 제거 후 기존 객체와 연결되지 않아 제외한 낮은 신뢰도 신호등 수 |
| `detected_crosswalk_count` / `crosswalk_candidate_count` | 연결 기준 통과 수 / 횡단보도 후보 수 |
| `crosswalk_diagnostics` | 검출·연결 상태, 기준 통과 수, 후보 목록의 `selected_crosswalk_index` |
| `association` | 선택 사유, 추적 번호, `tracking.tracker=botsort`, 횡단보도용 `tracking.camera_motion`, `selection_origin` |

`association.crosswalk_index`는 연결 기준 통과 목록의 인덱스입니다.
진단 목록의 연결 박스는 `crosswalk_diagnostics.selected_crosswalk_index` 또는 `crosswalk_status=used`로 찾습니다.
확인 중에는 최종 선택 인덱스·색상 신뢰도가 null이고 최종 색상은 unknown입니다.
영상마다 ID가 다시 시작하므로 서로 다른 영상의 같은 번호는 동일 객체를 의미하지 않습니다.

OpenCV 결과 영상은 영문 라벨을 사용합니다. TARGET·CANDIDATE·UNSELECTED 모두 객체 ID를 표시하고,
검출 신뢰도(det)와 색상 신뢰도(color)를 구분합니다. 테스트 앱처럼 횡단보도 박스·라벨,
소실점·연결선과 하단 횡단보도 진단 패널은 표시하지 않습니다. 횡단보도 검출·연결 판단과
반환 진단 데이터는 유지하며, 도보 모듈의 핑크색 횡단보도 마스크도 그대로 표시합니다.

## 실시간 전환 시 추가할 음성 안내

이번에는 음성 모듈·음원·영상 음성 삽입을 추가하지 않습니다. 후속 실시간 작업에서
테스트 앱의 최신 기준을 적용할 예정입니다.

- 같은 대상·같은 색을 3프레임·400ms 이상 확인 후 안내.
- 최초 초록불은 “초록불입니다. 다음 초록 신호를 기다려 주세요.”.
- 같은 대상의 연속 빨강↔초록 전환 시 변경 안내, 같은 색 반복 억제.
- 신호색 확인 이력이 있을 때만 2초 이상 확인 불가 구간에서 한 번 안내.
- 확인 불가 안내 후 재확인한 색은 같은 색이어도 한 번 안내.
- 재확인 초록불은 “초록불입니다.”. 후속 음성은 현재 문장이 끝난 뒤 순서대로 재생.

통합 영상은 원본 FPS와 영상 시각을 사용하며, 테스트 앱은 초당 최대 5회 처리합니다.
횡단보도 연결의 3프레임 조건은 5FPS에서 약 0.4초, 30FPS에서 약 0.067초입니다.
이 선택 조건에는 별도의 최소 400ms 검사가 없으며, 위 음성 확정 조건과 구분합니다.
직접 `predict(frame)`만 호출하면 호환용 연속 번호·200ms 간격을 사용하므로 실제 입력에서는
명시적인 촬영 시각을 전달해야 합니다.
